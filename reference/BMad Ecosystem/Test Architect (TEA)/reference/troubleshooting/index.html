Troubleshooting Guide

Troubleshooting Guide

Section titled “Troubleshooting Guide”

Installation Issues

Section titled “Installation Issues”

TEA installs as skills. npx skills add installs each one into your host’s skills folder, such as .claude/skills/ or .agents/skills/. It may use symlinks or copies. The commands below use .claude/skills/; substitute your host’s folder.

TEA Skills Not Found After Installation

Section titled “TEA Skills Not Found After Installation”

Symptom: After npx skills add bmad-code-org/bmad-method-test-architecture-enterprise, the TEA agent or workflows are not available.

Cause: The install did not finish, it went to a different scope (project or global) than the one your host reads, or the host was started before the skills existed.

Expect the bmad-tea agent, bmod-tea module, and eight direct workflows: bmad-tea-teach-me-testing and seven bmad-tea-* entries. Automate handles ATDD through red mode; Framework handles CI setup through CI scope. Restart the host or start a fresh chat after installing.

Section titled “Old Slash Commands Still Appear After 3.0”

An upgrade may leave old skill folders. Check project and global scopes; substitute your host’s skills directory for .claude/skills/.

For a global install, add --global. Move unmanaged old folders out after backup. Keep bmad-tea, bmod-tea, and new bmad-tea-* folders. Restart the host and verify its command list.

Install Hangs or Cannot Reach GitHub

Section titled “Install Hangs or Cannot Reach GitHub”

Symptom: npx skills add hangs, times out, or cannot fetch the repository.

Cause: The npm registry is unreachable or slow, or a firewall blocks GitHub. Check each before changing anything.

  • npm ping fails: the registry or proxy is the problem. Ask your administrator.
  • curl prints a connection error or a status other than 200: GitHub is blocked. See Install TEA Behind a Corporate Firewall.
  • The error names the npm cache (EACCES, integrity checksum failed): run npm cache verify, then retry. Run npm cache clean --force only if that fails.
  • The registry is a leftover from an old proxy and your organization allows the public one: note the value, then run npm config set registry https://registry.npmjs.org/. Restore it with the same command and the noted value.

TEA Says It Is Not Set Up

Section titled “TEA Says It Is Not Set Up”

Symptom: A TEA skill stops and asks you to run bmad setup tea.

Cause: _bmad/config.toml is missing or has no [modules.tea] table. The setup questions come from bmad setup tea.

Fix: Run bmad setup tea in the assistant chat. It needs uv and the bmad skill from BMad Method core; if the skill is missing, add it with npx skills add bmad-code-org/BMAD-METHOD --skill bmad bmod-core-tools.

TEA Offers to Install the Knowledge Base

Section titled “TEA Offers to Install the Knowledge Base”

Symptom: A TEA skill says the knowledge base is not installed and offers to install bmod-tea.

Cause: The bmod-tea skill is missing from the folder the TEA skills sit in. Skills find the knowledge base at ../bmod-tea/knowledge from their own folder, so bmod-tea must be installed beside them, in the same scope.

Fix: Accept the offer, or run npx skills add bmad-code-org/bmad-method-test-architecture-enterprise --skill bmod-tea yourself.

Custom TEA Skill Does Not Appear

Section titled “Custom TEA Skill Does Not Appear”

Symptom: A custom skill that used to appear in the bmad-tea menu is gone after an update.

Cause: TEA is a standalone module. Custom skills are not merged into TEA core automatically.

Fix: Install the custom skill, add it to the bmad-tea menu with an [[agent.menu]] entry in _bmad/custom/bmad-tea.toml, then start a fresh chat. See Extend TEA with Custom Skills.

Skill Execution Issues

Section titled “Skill Execution Issues”

GitHub Copilot Slash Command Fails with “No such file or directory”

Section titled “GitHub Copilot Slash Command Fails with “No such file or directory””

Symptom: A skill launched through GitHub Copilot in VS Code fails with an error such as can't open file 'C:\path\to\workspace\scripts\resolve_customization.py': [Errno 2] No such file or directory.

Cause: GitHub Copilot runs skill commands from the workspace root. Paths relative to the installed skill under .github/skills/ therefore fail to resolve.

Fix: Shipped TEA skills already anchor every path with {skill-root} or {project-root}. If you hit this in a skill you wrote, apply the same anchoring; see Extend TEA with Custom Skills.

Skill Starts But Produces No Output

Section titled “Skill Starts But Produces No Output”

Symptom: The skill runs but generates no test designs, reports, or tests.

Cause: The output directory is missing or not writable, test_artifacts is misconfigured, or the run stopped before its output step.

If the directory is correct and writable, read the agent’s final message for a completion line such as ✓ Test design complete. When a run stops early, the last step it names is where to look.

Subagent Fails to Execute

Section titled “Subagent Fails to Execute”

Symptom: The skill reports a subagent failure, for example “API test generation subagent failed”.

Cause: A subagent step file is missing, /tmp is not writable, the subagent returned an unparseable payload, or the runtime cannot launch parallel workers.

If the runtime cannot launch parallel workers, force the deterministic path under [modules.tea], with bmad setup tea or by editing _bmad/config.toml:

Knowledge Fragments Not Loading

Section titled “Knowledge Fragments Not Loading”

Symptom: The skill runs but never references knowledge base patterns such as test-quality or network-first.

Cause: The bmod-tea skill is missing or not beside the other TEA skills, or tea-index.csv or fragment files are missing.

{tea-knowledge} is ../bmod-tea/knowledge from the skill’s own folder.

Configuration Issues

Section titled “Configuration Issues”

Setup Questions Were Never Asked

Section titled “Setup Questions Were Never Asked”

Symptom: TEA runs with defaults you did not choose, or you want to change an answer.

Cause: The setup questions come from bmad setup tea.

Fix: Run bmad setup tea in the assistant chat. On an existing setup it shows each answer with its value and file, and changes the ones you name.

Config Values Ignored

Section titled “Config Values Ignored”

Symptom: TEA ignores the values you set or keeps old values after a config edit.

Cause: The value is in the wrong file or table, the TOML does not parse, a key is misspelled, a later layer overrides it, or the chat started before the edit. TEA reads config once at activation and does not reload mid-chat.

TEA keys belong under [modules.tea]. _bmad/custom/config.user.toml wins over _bmad/custom/config.toml, which wins over _bmad/config.toml. evaluations_folder and ci_platform are skill keys. Put evaluations_folder under [workflow] in _bmad/custom/bmad-tea-evaluate.toml and ci_platform under [workflow.ci] in _bmad/custom/bmad-tea-framework.toml. Red-mode settings go under [workflow.red] in _bmad/custom/bmad-tea-automate.toml. Files named bmad-tea-ci.toml or bmad-tea-atdd.toml are not read; run bmad migrate tea to move them. A _bmad/tea/config.yaml from an earlier install is not read by any skill.

If the key name matches Configuration, save the file, start a fresh chat, and re-run the skill.

Playwright Utils Integration Not Working

Section titled “Playwright Utils Integration Not Working”

Symptom: Skills produce no Playwright Utils references even though tea_use_playwright_utils is enabled.

Confirm the skill integrates Playwright Utils at all. Framework (TF and CI), Test Design (TD), Automate (TA and AT, red and expand), and Test Review (RV) integrate Playwright Utils. Trace and NFR Evidence Audit do not.

The same three checks apply to Pact.js Utils, which is also on by default: grep tea_use_pactjs_utils _bmad/config.toml, npm ls @seontechnologies/pactjs-utils, and ls .claude/skills/bmod-tea/knowledge/pactjs-utils-mandate.md.

Each integration needs its flag enabled and its package installed. With a missing package, generation uses the plain framework and Test Review skips the utility criteria. Run Framework (TF) or install the package directly:

If the package is installed and output is still vanilla, the mandate fragment did not load. Check that playwright-utils-mandate.md is present next to the other fragments and indexed in tea-index.csv:

Then start a fresh chat: fragment selection happens at step 01, so a run that already loaded the vanilla profile keeps it for the rest of the run.

Output and File Issues

Section titled “Output and File Issues”

Test Files Generated in Wrong Location

Section titled “Test Files Generated in Wrong Location”

Symptom: Test files are created in an unexpected directory.

Cause: test_artifacts resolves against the project root, so a misconfigured value or a shell sitting in a subdirectory moves the target.

Generated Tests Have Syntax Errors

Section titled “Generated Tests Have Syntax Errors”

Symptom: TEA generates tests with JavaScript or TypeScript syntax errors.

Cause: A framework mismatch, usually Playwright syntax emitted for a Cypress project or the reverse.

Fix: Name the framework and language explicitly in the prompt, for example “Generate Playwright tests using TypeScript”, then lint what came back:

File Permission Errors

Section titled “File Permission Errors”

Symptom: EACCES: permission denied when writing files.

Cause: The target directory is not writable, is owned by another user, or the disk is full.

Pact MCP Reports the Broker as Unreachable

Section titled “Pact MCP Reports the Broker as Unreachable”

Symptom: A skill says the broker was unreachable and fell back to provider source or an OpenAPI spec.

Cause: tea_pact_mcp defaults to "mcp", so TEA probes for the SmartBear MCP tools on any contract-testing step. Without a broker, that probe fails and the skill degrades on purpose.

Browser Automation Not Working

Section titled “Browser Automation Not Working”

Symptom: tea_browser_automation is set to auto, cli, or mcp, but outputs contain no browser features.

Cause: For cli or auto, the CLI is not installed globally. For mcp or auto, the MCP server is not configured in the IDE.

For MCP mode, add the server to your tool’s MCP config, then restart the IDE:

Performance Issues

Section titled “Performance Issues”

Skills Taking Too Long

Section titled “Skills Taking Too Long”

Symptom: A skill runs for several minutes without completing.

Cause: A large codebase to explore, many test files to review, or subagent overhead.

Fix: Scope the run to a directory, for example “Review tests in tests/e2e/checkout/”. Use automate for targeted generation and test-review for specific files. Check top for CPU and memory pressure.
