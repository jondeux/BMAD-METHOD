Map Your Tracker to the Ticket Tree

Sofia keeps the ticket tree as files and, once you connect a tracker, publishes it there. The files stay the working copy; the tracker is where the team sees the work. This page lists what each level becomes in each tracker, what your tracker has that the tree doesn’t, and how to map levels whose names don’t line up.

Map by What Each Level Does

Section titled “Map by What Each Level Does”

Tracker level names don’t match BMad’s. Linear has no Epic object, and in SAFe the Epic sits above the Feature. Match each level of your hierarchy to the BMad level that does the same job:

What the level does hereBMad level
Groups several product efforts, such as a programParent initiative
One outcome with its own requirementsInitiative
One increment that closes once its Done when holdsEpic
One change that fits a single build sessionStory, bug, spike

What Has No Counterpart

Section titled “What Has No Counterpart”
Your tracker hasThe ticket tree
Sprints or cyclesNo time boxes; work flows in build order. Keep running sprints in the tracker; Sofia doesn’t read or set them.
Fix versions or releasesNo release grouping, and none is synced. Keep releases in the tracker.
A backlog of all unstarted workbacklog/ holds only work that belongs to no epic. An unstarted story stays in its epic, as backlog, and publishes as To Do.
Epics that grow as long as the feature lastsAn epic gets a retrospective, then closes only after Sofia checks its Done when. Work it doesn’t need moves to another epic, so it can close.
Linear projectsNot tied to a ticket-tree level by default: epics are parent issues and initiatives stay local. The store can still set an issue’s project.
GitHub milestones used for releasesBMad uses milestones for initiatives. If yours mean releases, leave initiatives unpublished.

Which Way Changes Flow

Section titled “Which Way Changes Flow”

Nothing syncs on its own: Sofia publishes and reads the tracker during the board steps you run with her.

  • By default, she offers to publish the whole agreed breakdown once it’s validated. To publish each ticket only when it starts, set publication = "on_start" under [workflow] in _bmad/custom/bmad-agent-po.toml.
  • When she next syncs, status, assignee, and blocking links come back into the files. A story someone adds in the tracker under a published epic comes back as a new entry. When a description differs between the tracker and the file, she shows both and asks which to keep.
  • Tracker status doesn’t make a build skip work, and Sofia doesn’t push your files to Git.

Sofia publishes the tree she holds. There’s no step for adopting an epic that already exists in the tracker: plan the work with Sofia and let her publish it.
